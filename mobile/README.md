# SinoRus TradeLite — мобильный клиент (каркас экранов)

Мобильное приложение для платформы кооперации в трансграничной торговле
России и Китая. **Это каркас экранов**: разметка, навигация, тема,
локализация и структура данных готовы; бизнес-логика и обращения к серверу
пока заглушены.

> English version is not provided. Версия на китайском языке: **[README.zh.md](README.zh.md)**

- **Дисциплина:** «Технологии разработки мобильных приложений», ВлГУ
- **Проект:** «SinoRus TradeLite» — лёгкая платформа кооперации
- **Связанный сервер:** Django 4.2.30 (`Python Web/course_project`)
- **Этап:** проектирование экранов и навигации (после перечня функциональных требований)

## 2. Чего ещё нет (следующие шаги)

1. **Серверного API не существует.** В Django-проекте сейчас только
   серверный рендеринг HTML: в `requirements.txt` нет DRF, ни один
   view не возвращает JSON. Мобильный клиент физически не может
   подключиться, пока на сервере не появится слой API
   (перечень — в `src/api/client.ts`, там же разметка URL).
2. **Библиотеки из технологического стека не подключены.**
   Redux Toolkit / RTK Query, op-sqlite, Vision Camera, FCM / APNs,
   i18next, Keychain / Keystore, Jest / Detox — заменены
   зависимостями без нативных модулей, чтобы каркас запускался
   в Expo Go сразу. Точки замены помечены комментариями.
3. **Бизнес-логика.** Все формы отправляются в никуда; проверок
   полей нет; очередь офлайн-операций и разрешение конфликтов
   реализованы как демонстрация интерфейса, без сохранения.
4. **Нативные модули требуют dev-build.** Карта (`react-native-maps`)
   и камера (Vision Camera) в Expo Go не работают — нужен
   `npx expo prebuild` и сборка на устройстве.

## 3. Запуск

```bash
cd mobile
npm install
npm start               # запуск с автоматическим выбором IP в локальной сети
npm run start:tunnel    # если QR-код не подключается — режим туннеля
npm run start:usb       # по USB: сначала adb reverse tcp:8081 tcp:8081
npm run typecheck       # проверка типов
npm run check:i18n      # проверка полноты переводов (ru/zh/en)
```

Веб-версия (`w`) — самый быстрый способ посмотреть все экраны без
устройства: каркас полностью работает в браузере.

### QR-код не подключается? Скорее всего выбран не тот сетевой интерфейс

`npm start` — не просто псевдоним `npx expo start`: он ещё и **выбирает правильный IP**.

Expo берёт первый не-loopback IPv4. Если на машине включён прокси (режим TUN у
Clash / Mihomo создаёт виртуальный адаптер `198.18.0.1`), VirtualBox или VMware,
этот адрес оказывается первым, и QR-код ведёт на `exp://198.18.0.1:8081` —
внутренний адрес компьютера, недоступный с телефона.

`tools/start.mjs` исключает `127/8`, `169.254/16` (APIPA) и `198.18/15`
(fake-IP прокси), отбрасывает виртуальные адаптеры VirtualBox / VMware /
Hyper-V / Docker, отдаёт приоритет WLAN / Ethernet и передаёт результат
в `REACT_NATIVE_PACKAGER_HOSTNAME`. При запуске печатается выбранный адрес:

```
  Адрес в локальной сети: 192.168.0.108  (WLAN 2)
  Пропущены: 198.18.0.1 Mihomo, 192.168.56.1 Ethernet 3
```

| Команда | Когда использовать |
|---|---|
| `npm start` | телефон и компьютер в одной Wi-Fi-сети (по умолчанию) |
| `npm run start:tunnel` | разные сети, изолированная корпоративная сеть; при первом запуске предложит установить `@expo/ngrok` |
| `npm run start:usb` | Android по USB: `adb reverse tcp:8081 tcp:8081`, затем вручную открыть `exp://127.0.0.1:8081` |

`npm start` заодно создаёт `qr-dev.png` (1200 px, чистый чёрный на белом,
поля в 4 модуля). QR-код в терминале собран из блочных символов: реально он
всего 216×216 px, поля меньше 4 модулей, а если ячейка шрифта не 1:2 — он
растягивается в прямоугольник (замерено 216×332), и телефон его не читает.
**Простое правило: если QR в терминале выглядит не квадратным — он не считается.**
Не хотите возиться со шрифтом терминала — откройте `qr-dev.png` на весь экран.

Если всё равно не подключается, проверяйте по порядку: одна ли Wi-Fi-сеть
(гостевые сети часто изолируют клиентов) → брандмауэр (правило TCP 8081-8112
уже добавлено) → версия Expo Go (актуальная поддерживает SDK 58).

### Просмотр без установки зависимостей

В репозитории уже лежит собранный веб-сайт (`web-preview/`, исключён из git),
для его просмотра нужен маленький сервер с подстановкой путей:

```bash
npm run preview                                    # пересобрать в web-preview/
python tools/preview-server.py                     # открыть http://127.0.0.1:8125/
```

Каталог по умолчанию у сервера и `--output-dir` у `npm run preview`
обязаны совпадать, иначе сервер отдаст предыдущую сборку.

Зачем нужен `tools/preview-server.py`: `expo export` создаёт файлы вида
`workbench.html`, а маршрутизатор приложения читает `/workbench`;
`python -m http.server` в этом случае отдаёт «Unmatched Route».
Скрипт сопоставляет путь с файлом, а при отсутствии файла передаёт
управление клиентскому роутеру (нужно для динамических маршрутов).

## 7. Принятые решения

- **Разделение с веб-версией по характеру действий, а не по данным.**
  Веб-версия — планирование и массовая обработка; мобильная —
  действия «здесь и сейчас» (сканирование, фото, отметка, согласование).
- **FM10 не имеет аналога в веб-версии** — офлайн и очередь операций
  являются собственным свойством мобильного клиента.
- **Один источник данных для модулей** (`src/data/modules.ts`) —
  тот же приём, что и реестр `core/pages.py` на сервере.
- **Никаких секретов в репозитории**: адрес сервера вынесен в
  `src/api/client.ts`, файл `.env` добавлен в `.gitignore`.

## 8. Что исправлено относительно прототипа `1.html`

Направление прототипа `1.html` верное (карточка курса → быстрые действия →
таймлайн логистики → карточки товаров → нижняя навигация), поэтому главный
экран переделан по его макету. Но шесть типовых проблем однофайлового
прототипа устранены — таблица ниже годится как перечень для защиты.

### 8.1. Компоновка экрана

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Жёсткая «оболочка телефона» `max-w-[375px] h-[812px]`: на коротком экране появляется двойная прокрутка (оболочка + контент), нижняя навигация уходит за первый экран | В RN оболочки **нет**. Корень `flex: 1` делится на три строки: заголовок фиксирован, контент — `ScrollView` с `style={{ flex: 1 }}` (занимает всю оставшуюся высоту), нижняя навигация закреплена навигатором `Tabs` у нижней грани экрана. «Прокручивается только контент» обеспечивается самой структурой, без магии с высотами. Поворот, разделённый экран и развёрнутый складной аппарат пересчитываются через `useWindowDimensions` (`src/hooks/useResponsive.ts`). |

### 8.2. Структура компонентов

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Разметка, тексты и обработчики в одном HTML-файле; две карточки товара скопированы, правка в двух местах | Выделено 6 новых компонентов, всего стало **19**: `ExchangeRateCard` (курс), `QuickActions` (сетка быстрых действий), `Timeline` (таймлайн логистики и событий), `GoodsCard` (карточка товара), `Chip` (чип фильтра), `DataNote` (сноска об источнике данных). Данные собраны в `src/data/mock.ts`, обработчики быстрых действий — в `src/hooks/useQuickActions.ts`, фильтр во всём проекте один — `Chip` (заказы, документы, каталог). |

### 8.3. Стили

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Множество подписей `text-[10px]`; исторические узлы через `opacity-50` выходят светлее текущего; отступы, радиусы и тени заданы произвольно | Кегли сведены к 6 ступеням: `26 / 20 / 16 / 14 / 13 / 12` — ступень 10px **удалена**, `FONTS.tiny = 12` является нижней границей; межстрочный интервал вынесен в токен (`LINE_HEIGHT`). Радиусы только `8 / 12 / 16 / 20 / pill`, отступы только `4 / 8 / 12 / 16 / 24 / 32`, тени только `card / hero / bar` — свои значения на экранах не допускаются. Таймлайн: состоявшееся — залитая точка основного цвета и тёмный заголовок, текущее — кольцо подсветки и полужирный заголовок, и только «ещё не произошло» остаётся вторично-серым (по смыслу оно и должно быть слабее, но всё равно ≥ 12px). |

### 8.4. Интерактивность

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Быстрые действия и нижняя навигация — `div` с `cursor-pointer`: выглядят нажимаемыми, но ничего не делают; понятия цели нажатия нет | Всё заменено на нативный `Pressable` + `accessibilityRole="button"` + `accessibilityLabel`. Восемь быстрых действий привязаны к реальным маршрутам; нижняя навигация — настоящий навигатор `Tabs`. Добавлено три точки перехода: `/catalog` (каталог), `/goods/[id]` (карточка товара), `/logistics/track` (поиск по номеру). Поиск по грузу — настоящий: ввод номера → кнопка «Найти» → при совпадении показывается трек, при отсутствии — пустое состояние, при пустом вводе кнопка `disabled`. Демонстрационные действия сопровождаются явной подписью `demoActionHint`. |

### 8.5. Переключение языка

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Переключатель менял только `<h1>` и один `<p>`; длинные русские слова ломали кнопку в три строки | Полный словарь **212 ключей × 3 языка (ru / zh / en)**, покрывает все экраны; предоставляется `LangContext`, применяется мгновенно, без перезапуска (FR-045). `tools/check-i18n.mjs` проверяет: наборы ключей во всех трёх языках совпадают, а все ключи из `t('...')` существуют — при пропуске скрипт завершается с ненулевым кодом. Длинные русские подписи выдерживаются за счёт трёх вещей: нижняя граница кегля 12, допускаются две строки, ширина карточки считается по сетке, а не задана жёстко. |

### 8.6. Зависимости и данные

| Проблема прототипа | Как сделано сейчас |
|---|---|
| Зависимость от CDN Tailwind и FontAwesome (без сети всё ломается); значение `12.65` зашито, но подписано как «реальный курс» | **Никаких CDN**: иконки — глифы (при подключении — `@expo/vector-icons`), градиент — `expo-linear-gradient` (обычный npm-пакет, уже в `package.json`). Заголовок карточки курса изменён с «реального курса» на «Курс валют», источник и время обновления выводит компонент `DataNote` («демо-данные · время обновления»); тип `ExchangeRate` явно содержит поле `source: 'mock' \| 'api'` — при подключении API достаточно поменять значение, компонент не меняется. Аварийные состояния (номер не найден, пустой список, офлайн) имеют явные пустые состояния вместо молчаливого бездействия. |
